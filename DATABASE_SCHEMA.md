# AZmovies — Proposed Database Schema

**Status:** design only; no database, ORM schema or migrations exist. Phase 2 uses local TypeScript fixtures only and does not create or connect to a database. Target: PostgreSQL with Drizzle. Pin the actual server major when the provider is selected. Better Auth tables must be generated/checked against the pinned auth configuration, not guessed from this summary.

## 1. Modeling rules

- Application tables use snake_case and UUID primary keys. Better Auth's documented camelCase fields may be mapped explicitly; keep its generated schema authoritative.
- Store UTC `timestamptz` for events; use `date` for release/review dates.
- Use parameterized queries, foreign keys, explicit indexes and transactions for multi-record editorial changes.
- Do not store passwords, raw session tokens or API credentials in application/audit tables. Better Auth owns credential/session persistence.
- TMDB content, if permitted, is cached editorial metadata with provenance/expiry, not owned data or an unlimited training dataset.
- Manual movies require no provider ID. External-link authorization is independent of metadata import.

## 2. Relationship overview

```text
auth_users 1──N auth_sessions / auth_accounts / auth_two_factors
auth_users 1──N movies (created_by / updated_by)
auth_users 1──N audit_logs / import_jobs

movies N──M categories via movie_categories
movies N──M languages via movie_languages
movies 1──N external_links N──1 redirect_destinations
external_links 1──N redirect_daily_counts
movies 1──N import_jobs

categories: editorial collection / genre / language-oriented navigation
languages: original / spoken / verified display language roles
```

Auth rate-limit persistence is library-managed; its generated table/adapter is included in migrations after configuration review.

## 3. Authentication tables

| Logical table            | Required core contents                                                                                        | Notes                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `auth_users`             | id, name, email unique, email_verified, image nullable, created_at, updated_at, server-owned role             | Default role `user`; initial owner explicitly set to `admin` by bootstrap; role cannot be accepted from public input |
| `auth_sessions`          | id, user_id FK, library token, expires_at, ip_address/user_agent nullable, timestamps                         | Library-managed opaque session; no application copies in logs; 8-hour absolute expiry proposed                       |
| `auth_accounts`          | id, user_id FK, provider_id, account_id, credential hash nullable, provider token fields nullable, timestamps | Email/password only initially; no social provider tokens expected                                                    |
| `auth_verifications`     | id, identifier, value, expires_at, timestamps                                                                 | Generated library schema; no ad hoc reset tokens                                                                     |
| `auth_two_factors`       | user FK, encrypted TOTP secret, backup codes and library-required fields                                      | Exact columns generated by the pinned two-factor plugin; never expose secrets through admin APIs                     |
| Library rate-limit table | keyed counter/window state                                                                                    | Persistent/shared storage, not process memory; exact schema follows selected adapter                                 |

Generate auth schema with Better Auth CLI, review it, then manage through Drizzle migrations. Map model/field names intentionally. Test schema compatibility after every auth upgrade. Do not use auth `migrate` assumptions that apply only to its built-in adapter.

## 4. `movies`

| Field                   | Proposed type                 | Constraint / meaning                                                                                                    |
| ----------------------- | ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| id                      | uuid PK                       | Opaque application ID                                                                                                   |
| slug                    | text UNIQUE                   | Lowercase canonical path segment; reserved words rejected; retain stable slug after rename unless owner approves change |
| title                   | text NOT NULL                 | Trimmed, 1–200 characters                                                                                               |
| original_title          | text NULL                     | Optional factual original title                                                                                         |
| synopsis                | text NULL                     | Plain text, bounded length; no raw HTML                                                                                 |
| release_year            | smallint NOT NULL             | Initial allowed range 1878–2100; validate against release_date when present                                             |
| release_date            | date NULL                     | Unknown month/day must not be fabricated                                                                                |
| original_language_code  | text FK languages NULL        | ISO 639-1 source language if known                                                                                      |
| runtime_minutes         | integer NULL                  | Positive, bounded; never invent                                                                                         |
| quality_label           | text NULL                     | `SD`, `HD`, `FHD`, `4K` or null; vocabulary needs owner approval; null renders “Quality not specified”                  |
| quality_note            | text NULL                     | Editorial basis/qualification, not a download claim                                                                     |
| poster_source           | text NOT NULL                 | `provider`, `licensed_asset`, `none`; no arbitrary remote-fetch URL                                                     |
| poster_path             | text NULL                     | Provider-relative image path or approved local asset key, interpreted by source                                         |
| status                  | movie_status NOT NULL         | `draft`, `published`, `archived`; default draft                                                                         |
| metadata_source         | metadata_source NOT NULL      | `manual` or `tmdb`; provider enum expanded only after approval                                                          |
| tmdb_id                 | integer UNIQUE NULL           | Positive; absent for manual-only entries                                                                                |
| metadata_synced_at      | timestamptz NULL              | Actual successful provider fetch time                                                                                   |
| metadata_expires_at     | timestamptz NULL              | Proposed 30-day refresh deadline; never exceed applicable provider limit                                                |
| locked_fields           | text[] NOT NULL default empty | Allowlisted editorial overrides protected from refresh                                                                  |
| published_at            | timestamptz NULL              | Required for published status; set by server lifecycle action                                                           |
| version                 | integer NOT NULL default 1    | Optimistic concurrency for admin edits                                                                                  |
| created_by / updated_by | uuid FK auth_users NULL       | Restrict user deletion; null allowed for controlled system imports with audit actor context                             |
| created_at / updated_at | timestamptz NOT NULL          | Server-generated                                                                                                        |

**Checks/invariants:** published records require title/year/slug/published_at; provider-linked records require positive tmdb_id; provider poster paths cannot be absolute URLs; synced/provider expiry relationship is valid; locked_fields contains only supported metadata keys. Cross-field publication requirements are enforced in a transaction-tested service and database checks where practical.

`quality_label` is not supplied by TMDB as a release-file quality. Original language is not a dubbed-language claim. A publication may have no approved external action; never insert an unauthorized link merely to fill the UI.

## 5. Taxonomy and languages

### `categories`

- id UUID PK; slug unique; name 1–80 characters.
- kind: `collection`, `genre`, `language`.
- tmdb_genre_id integer nullable/unique when mapped; language_code nullable FK for language navigation.
- sort_order integer; is_active boolean; created_at/updated_at.
- Examples such as Bollywood/South Hindi Dubbed are **candidate editorial labels**, not a verified screenshot transcription.
- A collection is not automatically inferred from a language. Unpublish/deactivate rather than silently removing navigation history.

### `movie_categories`

- composite PK (movie_id, category_id), both FKs.
- category assignment changes and audit occur in the same transaction.
- index category_id/movie_id for filtered browsing.

### `languages`

- code text PK, ISO 639-1 initially; label required; sort_order/is_active.
- Owner confirms display vocabulary (for example Hindi/English/Tamil/Telugu); do not hardcode a regional assumption.

### `movie_languages`

- movie_id FK, language_code FK, role `original`, `spoken`, `display`.
- composite PK (movie_id, language_code, role); evidence/source note optional for editorial display/dub claims.
- Card language is derived from verified `display` entries; if unknown, use a truthful fallback rather than substituting production country.

## 6. Redirect authorization

### `redirect_destinations`

| Field                   | Type / rule                                                             |
| ----------------------- | ----------------------------------------------------------------------- |
| id                      | uuid PK                                                                 |
| hostname                | text UNIQUE; exact lowercase normalized host, not a wildcard domain     |
| path_prefix             | text NULL; normalized segment-boundary prefix, not a regular expression |
| label                   | text; official provider/service name                                    |
| policy_evidence         | text; why this destination class is permitted                           |
| is_active               | boolean default false; activation is an audited admin action            |
| created_by / updated_by | auth_users FK                                                           |
| created_at / updated_at | timestamptz                                                             |

Only HTTPS and standard port 443 are accepted by application policy. No userinfo, shortener or arbitrary user-controlled subdomain allowance. Hostname allowlisting alone is insufficient: each link still needs evidence.

### `external_links`

| Field                               | Type / rule                                                                     |
| ----------------------------------- | ------------------------------------------------------------------------------- |
| id                                  | uuid PK; internal only, never sent to public users                              |
| movie_id                            | uuid FK movies                                                                  |
| option_slug                         | descriptive public option selector; unique within a movie                       |
| destination_id                      | uuid FK redirect_destinations                                                   |
| target_url                          | text; canonical HTTPS URL, bounded length, validated against destination policy |
| label / provider_name               | text; truthful action description                                               |
| territory_codes                     | text[]; empty means unspecified, not guaranteed worldwide                       |
| authorization_evidence              | text; owner-reviewed permission/official-page basis, access-controlled          |
| status                              | link_status: `pending`, `approved`, `revoked`; default pending                  |
| approved_by / approved_at           | auth_user FK / timestamptz; required together for approved records              |
| review_by                           | date NULL; periodic review deadline where needed                                |
| expires_at                          | timestamptz NULL; authorization expiry, not movie release date                  |
| last_checked_at / last_check_result | nullable timestamp and bounded status code; no secrets/raw response bodies      |
| created_by / updated_by             | auth_user FK                                                                    |
| version                             | integer for concurrent review protection                                        |
| created_at / updated_at             | timestamptz                                                                     |

Approved-link check constraints require evidence and approval metadata. Any material target change returns the link to pending and clears approval; approval cannot be mass-assigned through a movie update. Revoked/expired links and inactive destinations fail at click time. Follow no caller-supplied redirect target.

**Page 3 fixture mapping (no database yet).** `ProviderLinkFixture` in `src/lib/link-fixtures.ts` is `server-only`: `id` maps to an internal primary key, `movieSlug` resolves the movie, `optionSlug` is a descriptive public selector, and `targetUrl` maps to the private `target_url`/destination. A future schema must enforce uniqueness for `(movie_id, option_slug)` and never expose link/database IDs or raw targets in public payloads. The persisted lifecycle must still add `pending`/`revoked`, evidence and approval metadata. Every prototype record is `fixture-placeholder`, and activation is also hard-disabled. The isolated v2 session-demo store is not a schema substitute: it has no server writes, audit trail or multi-user semantics.

### `redirect_daily_counts`

- link_id FK + UTC day composite PK; integer count nonnegative.
- Atomic aggregate increment only; no visitor IP, user agent, cookie ID or raw referrer.
- Analytics failure must not turn into an open redirect or expose a target. Retention/aggregation policy finalized before release.

## 7. Metadata jobs and audit

### `import_jobs`

- id UUID PK; provider; provider_movie_id nullable; movie_id nullable FK.
- operation `preview`, `import`, `refresh`, `purge`.
- status `queued`, `running`, `succeeded`, `failed`, `cancelled`.
- attempt count, requested_by FK, sanitized error_code, created/started/finished timestamps.
- Store a bounded normalized request context, not credentials or raw provider payloads.
- Prevent duplicate active import/refresh for the same provider movie with a partial unique index/transaction policy.
- Preview does not persist movie content. Import creates a draft; refresh respects locked_fields and never changes link approval/publication status.
- Retry/lease recovery must be idempotent. Provider search results are not automatically published.

### `audit_logs`

- id UUID PK; actor_id nullable FK; action; entity_type; entity_id nullable; request_id.
- redacted change summary JSONB; created_at.
- Record create/edit/archive/publish, category changes, destination activation, link submission/approval/revocation, import/refresh/purge and security-relevant admin actions.
- No update/delete API. Consider a separate append-only database role in production.
- Never include passwords, hashes, session tokens, TOTP secrets/recovery codes or unredacted private evidence.
- Agree retention with owner; proposed security audit retention 180 days, not yet implemented.

## 8. Query/index plan

| Access path                   | Initial index / strategy                                                                              |
| ----------------------------- | ----------------------------------------------------------------------------------------------------- |
| Published catalog             | `(published_at DESC, id DESC)` partial index WHERE status='published'                                 |
| Category catalog              | movie_categories(category_id, movie_id), then published ordering                                      |
| Movie detail                  | unique slug; public query also requires published status                                              |
| Provider dedupe               | unique tmdb_id; manual nulls do not collide                                                           |
| Title search                  | normalized title + PostgreSQL trigram index after extension availability is verified                  |
| Language/year/quality filters | movie_languages(language_code, movie_id); selective year/quality indexes chosen from EXPLAIN evidence |
| Admin review                  | external_links(status, review_by), movies(status, updated_at)                                         |
| Redirect lookup               | Unique movie/option selectors, then internal joined movie/destination status checks                   |
| Refresh scheduler             | metadata_expires_at partial index for permitted provider-linked records                               |
| Jobs                          | status/created_at and duplicate-active partial unique index                                           |
| Auth expiry                   | library-required user/token indexes and session expiry cleanup                                        |

Use a fixed allowlist for sort expressions. Escape literal `%`/`_` in substring search. Numeric pagination uses stable ordering and bounded page/pageSize; measure count/filter queries on 10,000 representative records before adding complexity. Do not concatenate user SQL or accept an arbitrary sort field.

## 9. Migration, seed and retention policy

1. Generate auth schema and app schema; inspect SQL and constraint names before applying.
2. Apply to a disposable real PostgreSQL database; run integration tests and migration status checks.
3. Use transactions and expand/contract for nontrivial changes; backup before production migration.
4. Seed only synthetic movies/taxonomy and a controlled test admin in development/test. Seed scripts must refuse production and must not contain real credentials.
5. Never seed live external movie destinations or scraped posters. Authorized production content is entered/reviewed separately.
6. Back up catalog/auth/audit data encrypted with access controls; test restoration. Exact retention/RPO/RTO awaits owner/host selection.
7. If TMDB is permitted, refresh proposed every 30 days and enforce purge well before the current six-month maximum; cease/purge as required on licence termination. [1](https://www.themoviedb.org/api-terms-of-use)
8. Purge expired auth/rate-limit/job data according to library/security policy; keep required audit history without collecting unnecessary visitor data.

## 10. Schema acceptance evidence required later

- Real migration apply/status/rollback or restore rehearsal, not just generated SQL.
- Unique provider ID/slug/category assignment and status checks.
- Manual movie without TMDB ID; provider refresh preserves locked fields.
- Draft/archived non-disclosure; concurrent edit conflict; link target change clears approval.
- Approved/expired/revoked/inactive destination behavior at the HTTP boundary.
- Auth generated-schema compatibility, session expiry and MFA enrollment/recovery.
- Query plans/latencies at the agreed catalog size.

All items are **Not run** in Phase 1.
